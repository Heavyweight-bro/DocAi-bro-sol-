# Doc.AI

Україномовний робочий простір для витягування структурованих даних із документів. Інтерфейс — React/Vite, сервер — Express.

## Що є в цій версії

- Корпоративний інтерфейс, налаштування назви компанії та адаптація до мобільного екрана.
- Незалежний вибір **OpenAI, Gemini або Anthropic**: API-ключ, модель, збереження та перевірка підключення. Автоматичного переходу на іншого провайдера немає.
- Підказки для промптів і готові інструкції для рахунків, договорів та виписок.
- Попередній перегляд, послідовна обробка у вкладці, повторна спроба, шаблони, пошук історії та експорт JSON.
- API обробки за шаблоном і читання результату за ID.

Підтримуються PDF, DOCX, XLSX/XLS, CSV, JSON, TXT, PNG, JPEG, WebP. Ліміт сервера — 10 MiB на файл; хостинг може мати менший. Старий формат `.doc` не підтримується.

Входу співробітників, ролей, ізоляції компаній, серверної черги та OAuth-входу до AI-провайдерів поки немає. Назва компанії змінює підпис робочого простору, але не створює окремої БД.

## Перший запуск на Mac / Linux

Потрібні Git, Node.js 22+ та npm.

```sh
git clone --branch improve/docai-workspace https://github.com/Heavyweight-bro/DocAi-bro-sol-.git "$HOME/DocAi-bro-sol-"
cd "$HOME/DocAi-bro-sol-"
npm ci
cp -n .env.example .env.local
npm run dev
```

Відкрийте [http://localhost:3000](http://localhost:3000). Інтерфейс і API працюють за однією адресою. Зупинка — `Ctrl+C`.

Для вже завантаженого репозиторію використайте його фактичну папку. Власні незбережені зміни спочатку збережіть окремим комітом.

```sh
cd "$HOME/DocAi-bro-sol-"
git fetch origin
git switch improve/docai-workspace
git pull --ff-only origin improve/docai-workspace
npm ci
npm run dev
```

`not a git repository` або `package.json ENOENT` означають, що команди виконуються поза папкою проєкту. Перейдіть до неї через `cd`.

## Підключення AI

Відкрийте **Налаштування** → введіть API-ключ і модель → **Зберегти** → **Перевірити** → виберіть провайдера за замовчуванням → **Зберегти простір**.

Без ключа доступні перегляд файлів і шаблони, але розпізнавання вимкнене. «Перевірити» отримує список моделей без надсилання документа; це не перевірка балансу, точності чи підтримки формату обраною моделлю. Моделі з `.env.example` — змінювані початкові значення.

Ключі можна також задати в `.env.local` і перезапустити сервер. Ключ середовища має пріоритет над локально збереженим. Локальні ключі зашифровані AES-256-GCM у `.data/settings/`; ключ шифрування лежить поруч з обмеженими файловими правами. Це не захист від адміністратора комп’ютера. Сервер не повертає збережені секрети в браузер.

У production ключі й параметри задає адміністратор через середовище, UI налаштувань доступний лише для перегляду. Не використовуйте префікс `VITE_` для секретів.

## Дані

Без Supabase у режимі розробки шаблони й успішні результати зберігаються в `.data/docai.json`. Це сховище для одного локального процесу, без автоматичної міграції в Supabase. Оригінали файлів обробляються в пам’яті й не архівуються.

PDF/зображення передаються обраному AI як файли; з DOCX витягується текст, з Excel — дані всіх аркушів. Відповідь перевіряється як JSON-об’єкт, але не за схемою полів конкретного шаблону. Перед передачею в облік перевірте дані.

Черга працює у відкритій вкладці. Запити синхронні; після закриття вкладки наступні файли не запускаються. Redis, worker, `jobId` і webhooks ще не реалізовані.

## Команди для розробника

```sh
npm run lint
npm run build
node --import tsx scripts/verify-providers.mjs
npx playwright install chromium
npm run test:smoke
```

Тести адаптерів використовують підмінені відповіді, без реального розпізнавання. Smoke-тест запускає тимчасовий сервер на порту 3100 з окремими локальними файлами. Запускайте його без справжніх AI/Supabase-реквізитів, включно з `.env.local`/`.env`, у development-режимі без `VERCEL`. Для встановленого Chromium можна задати `CHROMIUM_PATH`.

`npm run preview` показує лише frontend. Для API потрібен `npm run dev` або production-запуск з інструкції розгортання.
