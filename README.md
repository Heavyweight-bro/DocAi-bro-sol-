# Doc.AI

Україномовний робочий простір для витягування структурованих даних із документів. Інтерфейс — React/Vite, сервер — Express.

## Що є в цій версії

- **Вхід і ролі.** Перегляд / оператор / адміністратор; сесія в HttpOnly-cookie. CRM і скрипти — інтеграційний ключ (Bearer) з правами оператора. Без жодного користувача застосунок відкритий лише з цього комп’ютера (локальний режим розробки).
- **Незалежний вибір OpenAI, Gemini або Anthropic** + опційна ескалація: якщо дешева модель не пройшла схему, документ один раз перечитує сильніша.
- **Шаблони зі схемою перевірки**: вбудовані (рахунок, акт) або власні поля (тип, формат, обов’язковість) у конструкторі. Перевірки обліку: сума рядків = підсумок, ПДВ, контрольні суми ЄДРПОУ/РНОКПП та IBAN.
- **Екран перевірки**: оригінал поруч із полями, помилки підсвічені, редагування з повторною перевіркою, підтвердження/відхилення. Вихідна відповідь AI зберігається для метрик якості.
- **Експорт**: JSON/TXT, Excel (поля + рядки), реєстр документів у Excel і CSV для 1С / BAS / M.E.Doc.
- **Серверна черга** з повторами, відновленням перерваних завдань і захистом від дублювання (`Idempotency-Key`). У Supabase — черга в Postgres для кількох воркерів.
- **Webhook-и через outbox** з повторами та підписом із часовою міткою; **аудит** дій і вартості; **аналітика** витрат і точності для адміністратора.

Підтримуються PDF, DOCX, XLSX/XLS, CSV, JSON, TXT, PNG, JPEG, WebP. Ліміт сервера — 10 MiB на файл; хостинг може мати менший. Старий формат `.doc` не підтримується.

Ізоляції кількох компаній в одному розгортанні поки немає: одна інсталяція = одна компанія. Входу через SSO/OAuth немає.

## Перший запуск на Mac / Linux

Потрібні Git, Node.js 22+ та npm.

```sh
git clone --branch improve/docai-workspace https://github.com/Heavyweight-bro/DocAi-bro-sol-.git "$HOME/DocAi-bro-sol-"
cd "$HOME/DocAi-bro-sol-"
npm ci
cp -n .env.example .env.local
npm run dev
```

Відкрийте [http://localhost:3000](http://localhost:3000). Інтерфейс і API працюють за однією адресою. Зупинка — `Ctrl+C`.

Для вже завантаженого репозиторію використайте його фактичну папку. Власні незбережені зміни спочатку збережіть окремим комітом.

```sh
cd "$HOME/DocAi-bro-sol-"
git fetch origin
git switch improve/docai-workspace
git pull --ff-only origin improve/docai-workspace
npm ci
npm run dev
```

`not a git repository` або `package.json ENOENT` означають, що команди виконуються поза папкою проєкту. Перейдіть до неї через `cd`.

## Тестовий вхід і демо

- **admin / admin** — додайте `DOCAI_DEMO_ADMIN=true` у `.env.local` і перезапустіть `npm run dev`. Працює лише локально: у production (`NODE_ENV=production`, Vercel) змінна ігнорується.
- **Демо-простір** з синтетичними документами: `npm run demo:seed`, потім `npm run demo` → http://localhost:3001 (admin / admin). Дані — в `.data-demo/`, ваша `.data/` не змінюється.
- **Сайт продукту**: `npm run site` → http://localhost:4173 (папка `site/`, відео — `site/media/docai-presentation.mp4`).

## Користувачі

Поки користувачів немає, застосунок працює без входу, але лише з цього комп’ютера. Перший користувач вмикає обов’язковий вхід для всіх:

```sh
npm run user -- add you@company.ua admin "Ваше ім’я"
```

Далі адміністратор додає людей у **Налаштування → Користувачі та ролі**. На сервері (production) користувачі задаються змінною `DOCAI_USERS`, хеш пароля дає `npm run user -- hash you@company.ua admin`; також потрібен `DOCAI_SESSION_SECRET`. Деталі — [Розгортання](DEPLOYMENT_GUIDE.md).

## Підключення AI

Відкрийте **Налаштування** → введіть API-ключ і модель → **Зберегти** → **Перевірити**.

Документи йдуть лише до **провайдера за замовчуванням**. Якщо попередній default був без ключа, після збереження ключа цей провайдер стає основним автоматично.

Без ключа доступні перегляд файлів і шаблони, але розпізнавання вимкнене. «Перевірити» отримує список моделей без надсилання документа; це не перевірка балансу, точності чи підтримки формату обраною моделлю.

Ключі можна також задати в `.env.local` і перезапустити сервер. Ключ середовища має пріоритет над локально збереженим. Локальні ключі зашифровані AES-256-GCM у `.data/settings/`; ключ шифрування лежить поруч з обмеженими файловими правами. Це не захист від адміністратора комп’ютера. Сервер не повертає збережені секрети в браузер.

У production ключі й параметри задає адміністратор через середовище, UI налаштувань доступний лише для перегляду. Не використовуйте префікс `VITE_` для секретів.

## Дані

Без Supabase у режимі розробки шаблони й результати — у `.data/docai.json`, черга — `.data/jobs.json`, оригінали — `.data/files`, аудит і outbox — `.data/settings/`. Це сховище для одного процесу. З Supabase усе це живе в Postgres (схема — [`db/schema.sql`](db/schema.sql)), тож можна запускати кілька серверів і воркерів.

PDF/зображення передаються обраному AI як файли разом із текстом усіх сторінок; з DOCX витягується текст, з Excel — дані всіх аркушів. Для шаблонів зі схемою результат перевіряється і чекає підтвердження людиною; для решти — лише перевірка, що це JSON-об’єкт або текст.

## Команди для розробника

```sh
npm run lint            # TypeScript
npm run build
npm test                # lint + unit (vitest) + інтеграційні тести API/черги/входу
npx playwright install chromium
npm run test:e2e        # браузерні сценарії: smoke, вхід/ролі, екран перевірки й експорт
npm run test:pg         # Postgres-режим у Docker (PostgreSQL + PostgREST), кілька воркерів
npm run worker          # окремий процес воркера
npm run user -- list    # користувачі
```

Тести не звертаються до справжніх AI/Supabase: використовуються локальні імітації OpenAI API та PostgREST. Кожен тест запускає сервер на вільному порту з тимчасовими даними. Для встановленого Chrome можна задати `CHROMIUM_PATH`. CI — `.github/workflows/ci.yml`.

`npm run preview` показує лише frontend. Для API потрібен `npm run dev` або production-запуск з інструкції розгортання.
