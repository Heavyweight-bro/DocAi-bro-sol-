# Документація API DocuParse

Цей документ описує, як підключитися до вашого додатку DocuParse через API та автоматизувати процес витягування даних з документів.

## Базова URL-адреса

Усі запити повинні надсилатися на базову URL-адресу вашого розгорнутого додатку. 
Наприклад: `https://<ваш-додаток>.run.app`

---

## 1. Парсинг документів

Це основний ендпоінт для завантаження файлу та отримання структурованих даних у форматі JSON.

### 1.1. Парсинг за допомогою існуючого шаблону

Використовуйте цей метод, якщо ви вже створили шаблон (тип документа) в інтерфейсі (наприклад, з ідентифікатором `invoice`).

**Запит:**
- **Метод:** `POST`
- **Шлях:** `/api/parse/:slug` (де `:slug` — це ідентифікатор вашого шаблону, наприклад `/api/parse/invoice`)
- **Content-Type:** `multipart/form-data`
- **Тіло запиту:**
  - `document`: Файл, який ви хочете обробити (PDF, DOCX, XLSX, JPG, PNG).

**Приклад cURL:**
```bash
curl -X POST https://<ваш-додаток>.run.app/api/parse/invoice \
  -F "document=@/шлях/до/вашого/файлу/invoice_123.pdf"
```

### 1.2. Парсинг з власним промптом (без шаблону)

Якщо ви хочете передати промпт безпосередньо в запиті, не створюючи шаблон.

**Запит:**
- **Метод:** `POST`
- **Шлях:** `/api/parse`
- **Content-Type:** `multipart/form-data`
- **Тіло запиту:**
  - `document`: Файл для обробки.
  - `prompt`: (Опціонально) Текстовий опис того, які дані потрібно витягнути.

**Приклад cURL:**
```bash
curl -X POST https://<ваш-додаток>.run.app/api/parse \
  -F "document=@/шлях/до/файлу/contract.docx" \
  -F "prompt=Витягни імена сторін, дату підписання та загальну суму договору у форматі JSON."
```

**Успішна відповідь (200 OK):**
```json
{
  "id": 15,
  "originalName": "invoice_123.pdf",
  "typeSlug": "invoice",
  "extractedData": {
    "invoiceNumber": "INV-2023-001",
    "date": "2023-10-25",
    "totalAmount": 1500.00,
    "currency": "USD",
    "items": [
      { "name": "Послуги розробки", "quantity": 1, "price": 1500.00 }
    ]
  }
}
```

## 2. Управління шаблонами (Типами документів)

Ви можете програмно отримувати, створювати, оновлювати та видаляти шаблони.

### 2.1. Отримати всі шаблони
- **Метод:** `GET`
- **Шлях:** `/api/types`

**Приклад cURL:**
```bash
curl https://<ваш-додаток>.run.app/api/types
```

### 2.2. Створити новий шаблон
- **Метод:** `POST`
- **Шлях:** `/api/types`
- **Content-Type:** `application/json`

**Приклад cURL:**
```bash
curl -X POST https://<ваш-додаток>.run.app/api/types \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Договір оренди",
    "slug": "rent-agreement",
    "prompt": "Витягни орендодавця, орендаря, адресу обʼєкта та місячну плату."
  }'
```

### 2.3. Оновити існуючий шаблон
- **Метод:** `PUT`
- **Шлях:** `/api/types/:id` (де `:id` — це числовий ID шаблону)
- **Content-Type:** `application/json`

**Приклад cURL:**
```bash
curl -X PUT https://<ваш-додаток>.run.app/api/types/1 \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Оновлений Інвойс",
    "slug": "invoice",
    "prompt": "Новий промпт для інвойсу..."
  }'
```

### 2.4. Видалити шаблон
- **Метод:** `DELETE`
- **Шлях:** `/api/types/:id`

**Приклад cURL:**
```bash
curl -X DELETE https://<ваш-додаток>.run.app/api/types/1
```

## 3. Історія документів

### 3.1. Отримати історію розпізнаних документів
- **Метод:** `GET`
- **Шлях:** `/api/documents`

**Приклад cURL:**
```bash
curl https://<ваш-додаток>.run.app/api/documents
```

**Відповідь:**
Повертає масив об'єктів з інформацією про раніше завантажені файли та їх витягнуті дані (`extractedData`).

---

## Обробка помилок

Якщо щось піде не так, API поверне відповідний HTTP статус (наприклад, `400 Bad Request` або `500 Internal Server Error`) та JSON об'єкт з описом помилки:

```json
{
  "error": "Текст помилки, наприклад: Файл не надано"
}
```
