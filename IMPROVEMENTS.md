# Зміни та подальший розвиток

## Реалізовано

### P0 — безпека й надійність
- **Вхід і ролі** (`server/auth.ts`): viewer / operator / admin, підписана HttpOnly-cookie (SameSite=Strict, Secure у production), scrypt-хеші паролів, обмеження спроб входу, інвалідизація сесій при зміні пароля. Користувачі — `DOCAI_USERS` (production) або локальний файл (розробка, керування з UI чи `npm run user`).
- **Закрито обхід інтеграційного ключа**: раніше будь-який клієнт із заголовком `Origin`, рівним `Host`, отримував доступ до API. Тепер `Origin` — лише захист від CSRF; доступ дають сесія, Bearer-ключ або loopback у розробці без користувачів.
- **Права на шаблони, налаштування, аудит** — тільки admin; обробка й рішення — operator.
- **Черга**: один документ на завдання (невдалі спроби не засмічують історію), статус job `failed` при остаточній помилці AI, lease і відновлення завислих `processing`, FIFO, видалення проміжних файлів, опційний термін зберігання архіву.
- **Помилки 5xx** без внутрішніх деталей (є `requestId`), заголовки безпеки, монотонні ID документів, `Idempotency-Key` у межах одного викликача.
- **Тести й CI**: інтеграційні сценарії на вільних портах з імітацією OpenAI; GitHub Actions.

### P1 — цінність для бухгалтера
- **Екран перевірки**: оригінал поруч із полями, таблиці рядків, підсвічені помилки/попередження, редагування з повторною перевіркою, збереження вихідної відповіді AI, заморожування підтверджених документів, журнал виправлень.
- **Перевірки обліку**: сума рядків (+ ПДВ) = підсумок, `quantity × price`, ставка ПДВ, контрольні суми ЄДРПОУ/РНОКПП та IBAN, коректність дат.
- **Конструктор схем** для власних шаблонів (поля, типи, формати, обов’язковість; автозаповнення з прикладу JSON у промпті).
- **Експорт**: Excel одного документа (поля + рядки), реєстр у Excel і CSV для 1С / BAS / M.E.Doc (UTF-8 BOM, `;`, десяткова кома).

### P2 — масштаб і витрати
- **Черга в Postgres** (Supabase) з `FOR UPDATE SKIP LOCKED`: кілька воркерів, окремий процес `npm run worker`, cron-ендпоінт для Vercel; файли завдань у БД.
- **Webhook outbox** з повторами (до 24 год), ручним повтором і підписом із часовою міткою (`X-DocAI-Signature-256`).
- **Аудит у БД**, спільний для всіх вузлів.
- **Ескалація моделі**: дешева модель → сильніша, лише якщо схема не пройдена; вартість обох спроб у звіті.
- **Аналітика** для адміністратора: витрати й документи за днями, моделі, шаблони, точність з першого разу.
- Виправлено оцінку вартості: раніше ціна моделі не знаходилась через префікс провайдера (`openai/gpt-4o-mini`) і завжди бралась середня.
- `App.tsx` розділено на компоненти (Templates, History/Review, Analytics, API, Preview, Login, Users); модульні тести на vitest.

## Поточні обмеження

- **Одна компанія на розгортання**: немає ізоляції кількох компаній (multi-tenant) в одній БД.
- Немає SSO/OAuth-входу; користувачі production задаються змінною середовища (змінити роль = перезапуск).
- Файли для черги в Postgres зберігаються в БД (base64); для великих обсягів краще Supabase Storage.
- Оцінка вартості орієнтовна; для нових моделей задайте `DOCAI_MODEL_PRICES`.
- Реальні AI-запити, реальний проєкт Supabase і Vercel-розгортання не перевірялися; Postgres-режим перевірено на PostgreSQL 17 + PostgREST.
- `.doc` не підтримується; скановані документи залежать від якості розпізнавання моделі.

## Наступні кроки

1. **Кілька компаній**: `workspace_id` у всіх таблицях, прив’язка користувачів до компанії, RLS-політики.
2. **SSO** (Google Workspace / Microsoft Entra) і керування користувачами в БД.
3. **Надходження документів**: поштова скринька, Telegram-бот, папка в хмарі.
4. **Якість**: підсвічування місця поля в оригіналі, впевненість моделі, навчальні приклади з виправлень.
5. **Інтеграції**: прямий обмін з 1С/BAS, M.E.Doc, Checkbox; шаблони XML.

## Статус перевірок

`npm test` (TypeScript, vitest, схеми, адаптери, черга, воркер, вхід/ролі, P2), `npm run test:e2e` (браузер: smoke, вхід, екран перевірки, експорт, аналітика) і `npm run test:pg` (Postgres + PostgREST у Docker, два воркери) проходять локально.
